## 1. 目标与产品定位

UE-Agent 的用户入口从“模型工作台”调整为“长护险经营决策总览”。

系统分为三类页面：

1. 总览仪表盘：查看全部城市的经营结果、趋势、对比和风险。
2. 城市项目：按城市配置参数、运行公式、保存场景和结果快照。
3. 政策资料：管理政策文件、数据源、结构化字段和审核状态。

项目配置和政策资料产生的数据，经过保存、计算或审核后，进入统一的数据聚合层，再由总览仪表盘展示。

## 2. 已确认的核心决策

### 2.1 首页入口

首页 `/` 是全部城市总览，不再展示工作台介绍页。

首页默认进入全局视图，也可以切换到单个城市或多城市对比视图。

### 2.2 城市与项目关系

当前 MVP 继续保留“一城市一个项目”的配置方式。项目内部可以包含多个测算场景。用户界面不再突出 U1 城市选址这个技术阶段名称，而是使用“城市项目”。

`/u1` 和 `/projects/{projectId}/u1` 继续保留兼容入口，后续分别跳转到城市项目列表或对应城市项目详情页。

### 2.3 全局默认场景规则

全局仪表盘每个城市只选取一条最新有效结果：

- 按测算完成时间 `calculatedAt` 选择最新结果，而不是按参数修改时间选择。
- 只纳入状态为 `calculated` 或 `confirmed` 的结果快照。
- 参数修改后尚未重新测算的场景标记为 `stale`，继续保留上一条已计算结果，但在仪表盘标记“待重算”。
- 没有任何有效结果的城市显示“暂无有效测算结果”，不计入金额、利润和现金流汇总。
- 每条结果保存场景名称、测算完成时间、模型版本和完整输入快照。

### 2.4 数据覆盖原则

- 项目参数是测算输入的业务确认值。
- 政策解析结果在人工审核前只能作为候选参考值。
- 已确认政策字段可以作为项目参数的一键参考值，但不能静默覆盖已保存的业务输入。
- 核心财务结果只由确定性计算引擎生成，前端和大模型不直接计算财务结果。
- 缺失、真实零值、不适用、过期和待审核必须使用不同状态表达。

## 3. 整体信息架构

### 3.1 主导航

主导航收敛为四个入口：

1. 总览
2. 城市项目
3. 政策资料
4. 参数设置

“工作台”从主导航移除。“U1 城市选址”从主导航移除，保留兼容路由。模型版本、系统配置和参数定义进入参数设置，不放入首页。

### 3.2 数据流

```text
城市项目参数
  -> 场景保存
  -> 确定性计算引擎
  -> 结果快照
                         -> Dashboard 聚合 API -> 全局视图
政策原始文件/网页
  -> 解析候选字段
  -> 人工审核
  -> 已确认政策事实
                         -> Dashboard 聚合 API -> 单城市视图
城市基础数据/市场资料
  -> 来源与时点记录
  -> 有效数据集
                         -> Dashboard 聚合 API -> 城市对比
```

仪表盘不直接读取并在浏览器中聚合项目原始数据。聚合口径由服务端统一计算，前端只负责筛选、展示和跳转。

## 4. 总览仪表盘设计

### 4.1 顶部上下文栏

顶部提供：

- 视图切换：全部城市、单个城市、多城市对比。
- 城市选择器。
- 场景规则提示：最新有效场景。
- 统计周期：12 个月、24 个月。
- 数据更新时间。
- 刷新数据入口。

仪表盘默认为只读。所有编辑动作通过“进入城市项目”或“进入政策资料”完成。

### 4.2 核心指标区

默认展示六项指标：

- 有有效结果的城市数量。
- 总目标客户规模。
- 总预计月收入。
- 总预计月净利润。
- 总初始投资。
- 待确认问题数量。

回本周期不进行简单求和。全局视图使用“回本周期中位数”作为概览指标，并在城市对比区域展示回本周期分布。所有聚合金额使用千分位格式，负数显示明确负号。

### 4.3 经营趋势区

主趋势图展示：

- 总收入。
- 总净利润。
- 累计现金流。

默认展示全城市合计趋势。用户勾选城市后，可以增加城市明细线；为避免线条过多，默认最多同时突出五个城市，其余城市通过筛选查看。

### 4.4 城市比较区

使用真实数值和可解释图形展示：

- 市场规模与回本周期散点图。
- 初始投资与 24 个月累计净利润横向条形图。
- 平台期月收入、月净利润和成本结构对比。
- 数据完整度和待确认问题数量。

首版不生成未经业务确认的单一综合评分，也不使用雷达图强行压缩不同量纲。后续如需要综合评分，必须先由业务确认指标权重和计算方法。

### 4.5 政策与风险区

展示：

- 最近更新政策的城市。
- 政策资料缺失或过期的城市。
- 待人工审核的政策文件。
- 影响测算结果的政策字段变化。
- Excel 疑似问题和待业务确认项。
- 项目参数已修改但结果尚未重算的城市。

每项提醒都必须提供来源城市、关联项目或政策文件，以及下一步操作入口。

### 4.6 单城市视图

切换到单城市后展示：

1. 城市基本信息和数据更新时间。
2. 最新场景、模型版本和测算状态。
3. 收入、成本、利润和现金流趋势。
4. 成本结构拆解。
5. 关键参数摘要。
6. 政策影响字段。
7. 待业务确认问题。
8. 进入城市项目配置的入口。

单城市视图不直接展开全部公式参数。详细参数始终在城市项目页面维护。

### 4.7 响应式行为

- 桌面端使用 12 列网格。
- 平板端图表按两列或单列降级。
- 手机端 KPI 横向滚动，图表单列展示。
- 城市对比表改为可展开的城市卡片。
- 筛选器改为顶部抽屉。
- 政策和风险提醒不能因为屏幕变窄而隐藏，只能改变展示方式。

## 5. 城市项目设计

### 5.1 项目列表页

项目列表展示：

- 城市和区县。
- 当前最新场景。
- 最新测算时间。
- 测算状态。
- 回本周期。
- 平台期月净利润。
- 数据完整度。
- 待确认问题数。

主要操作：打开项目、编辑参数、复制场景、查看结果、重新测算。

### 5.2 项目详情页

顶部展示项目上下文：城市、区县、站点模式、当前场景、模型版本、最近测算时间和状态。

参数按以下业务区块分组：

- 城市与市场。
- 政策与服务。
- 站点条件。
- 成本与投资。
- 发展阶段。
- 效率与风险。
- 辅助收入。
- 进入模式。

参数页面使用分组折叠或左侧锚点导航，不再把全部字段堆成一张长表。每个参数显示名称、当前值、单位、来源、更新时间、人工覆盖状态和是否影响测算。

底部操作统一为：保存草稿、运行测算、复制当前场景、确认结果。

### 5.3 场景和结果状态

```text
draft -> stale -> calculating -> calculated -> confirmed
                         \-> failed
```

- `draft`：新建或正在编辑。
- `stale`：输入发生变化，原结果不再对应当前输入。
- `calculating`：正在运行模型。
- `calculated`：结果与当前输入一致。
- `confirmed`：有权限角色确认结果。
- `failed`：模型运行失败或被必要输入阻断。

结果快照不可变。重新测算会生成新快照，不覆盖历史快照。

## 6. 政策资料中心设计

### 6.1 政策总览

政策总览按全局和城市筛选展示：政策文件状态、最近更新时间、待审核文件、数据源状态、关键字段缺失城市和受政策变化影响的项目。

### 6.2 城市政策详情

城市政策详情包括：政策文件、原文、AI 解读、服务对象范围、服务单价、基金支付比例、服务时长、准入条件、人员配置、场地设备要求、生效时间、来源和版本历史。

### 6.3 数据源与文件管理

支持：

- 官方网页或公开数据源配置。
- Word、Excel、PDF 上传。
- 原始文件保存和文件指纹记录。
- 解析任务状态。
- AI 提取候选字段。
- 人工审核和发布。
- 数据撤回和版本历史。

文件状态为：

```text
uploaded -> parsing -> review_pending -> approved
                                  \-> rejected
```

AI 提取内容在 `review_pending` 状态下不得参与正式测算，也不得直接覆盖项目参数。只有 `approved` 的政策事实可以作为项目参数参考值，并进入仪表盘政策指标。

## 7. 统一数据模型

首期在现有项目和场景模型基础上增加以下概念：

### City

保存省、市、区县及行政区划编码，作为项目、政策和城市指标的统一关联对象。

### CityMetric

保存城市基础数据和市场指标，包括指标编码、值、单位、适用区域、统计期、来源、可信度、状态和更新时间。

### CalculationSnapshot

保存项目场景的不可变计算结果，包括项目 ID、场景 ID、输入快照、结果快照、模型版本、计算时间、状态和问题列表。

### PolicyDocument

保存原始政策文件、来源、适用区域、发布和生效时间、文件指纹、审核状态和版本关系。

### PolicyFact

保存从政策文件中提取并经审核的结构化字段，例如支付比例、单价、服务对象、准入条件和人员要求。

### DataSource

保存官方网页、公开接口、上传文件或人工录入等来源配置，以及抓取、解析和审核状态。

## 8. Dashboard API 设计

建议新增以下服务端接口：

```text
GET  /api/dashboard/overview
GET  /api/dashboard/cities
GET  /api/dashboard/cities/{cityId}
GET  /api/dashboard/compare
GET  /api/dashboard/policy-summary
GET  /api/dashboard/issues
```

`/api/dashboard/overview` 至少支持：

- `scope=global|city|compare`
- `cityIds`
- `period=12|24`
- `scenario=latest`
- `includeStale=true|false`

服务端负责选择每个城市的最新有效结果、执行聚合、过滤失效数据并返回数据状态。前端不复制聚合公式。

现有项目和场景接口继续保留，并在保存计算结果时产生 `CalculationSnapshot`。现有 U1 计算引擎继续作为确定性计算域使用。

## 9. 异步、空数据和错误状态

每个总览模块必须支持：加载、空数据、部分数据、数据过期、计算失败和无权限状态。

- 没有城市结果时显示引导进入城市项目。
- 城市缺少部分字段时显示数据完整度，不用 0 替代未知值。
- 结果待重算时保留旧结果并显示失效提示。
- 政策文件待审核时显示候选状态，不纳入正式政策指标。
- 聚合接口失败时保留筛选条件和重试入口。
- 单个城市计算失败不能阻断其他城市的总览显示，只在该城市显示异常状态。

## 10. 开发阶段

### 阶段一：总览仪表盘骨架

完成首页信息架构、全局和单城市视图切换、筛选器、图表组件和空数据状态。使用当前已有项目结果和前端 fixture 验证布局。

### 阶段二：结果快照与聚合 API

扩展现有项目和场景保存逻辑，生成不可变计算结果快照，新增 dashboard 聚合接口，实现城市结果同步到首页。

### 阶段三：城市项目页面重构

移除 U1 作为主导航名称，保留公式参数和场景能力，增加 stale、calculated、confirmed 状态以及历史快照查看。

### 阶段四：政策资料中心

完成政策总览、城市政策详情、文件上传、解析队列、人工审核和政策字段映射。

### 阶段五：真实数据源与生产基础设施

在数据口径稳定后接入 PostgreSQL、文件存储、用户权限、自动采集和定时刷新任务。自动采集不得绕过人工审核直接进入正式测算。

## 11. 验收标准

1. 首页默认展示全部城市总览。
2. 总览可以切换到单个城市和多城市对比。
3. 每个城市默认只取最近一次成功测算的有效结果。
4. 参数修改后未重新测算的城市明确显示待重算状态。
5. 新建或更新城市项目并成功测算后，结果可以在首页聚合展示。
6. 仪表盘金额、客户和趋势数据与结果快照口径一致。
7. 政策文件支持上传、解析候选字段和人工审核状态。
8. 未审核政策内容不会覆盖项目参数，也不会进入正式政策指标。
9. 政策审核通过后可以作为项目参数参考值并同步到总览。
10. U1 旧路由可以兼容跳转，但主导航不再出现 U1 城市选址。
11. 缺失、过期、待审核和待重算数据不会被静默当成有效零值。
12. 核心财务结果仍由确定性计算引擎产生。

## 12. 明确不在本轮范围内

- 立即接入全国所有城市的实时政策爬虫。
- 自动发布未经人工审核的政策解析结果。
- 直接生成未经确认的综合城市评分。
- 将总览仪表盘改造成可直接编辑几十个公式参数的页面。
- 首期引入复杂地图路径优化。
- 在本轮同时完成生产数据库、账号权限和正式部署。

## 13. 已验证的实现备注（2026-09-08）

- 图表实现采用 Recharts，原因是仓库前端规范已批准 Recharts，并要求避免新增未批准的图表依赖；图表仍保持客户端隔离、空数据状态和单位化 Tooltip。
- 开发版继续使用本地 JSON 与 `policy_files/` 窄目录保存政策元数据和原始文件，不上传真实个人信息或调用第三方解析服务。
- 政策解析接口采用显式候选字段契约：上传后进入 `uploaded`，提交候选后进入 `review_pending`，只有人工 `approve` 后才进入政策汇总；项目参数不会被静默覆盖。
