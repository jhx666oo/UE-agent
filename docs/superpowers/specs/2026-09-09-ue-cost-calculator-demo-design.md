# UE Agent 城市成本测算 Demo 设计

## 1 设计结论

UE Agent 的首版定位是一个公开访问的城市成本测算网站，不是传统业务管理系统。网站以城市为核心对象，严格复刻《长护险三阶段UE模型_v2.1 (1).xlsx》的控制台字段、公式和结果结构。

Demo 阶段不实现登录页、账号体系、角色权限和审批流。所有访问者都可以查看仪表盘、修改普通参数、新增城市、运行测算、配置政策官网来源、触发爬取和导出数据。页面需要明确展示“Demo 数据”，不得接入个人敏感信息。

## 2 信息架构

主导航只有四项：

1. 总览：展示全部城市的成本、收入、利润、现金流和政策数据状态。
2. 城市测算：新增城市、配置参数、运行 24 个月测算和查看结果。
3. 政策资料：配置公开官网链接，一键爬取原文，查看解析结果和建议值。
4. 城市对比：比较多个城市的成本、收入、利润、回本周期和数据状态。

“工作台”“项目管理”“U1 城市选址”和独立的“参数设置”不作为主导航。Excel 的核心指标卡、月度投影表和阶段汇总表分别映射为网站的 KPI、趋势图和阶段分析。

## 3 数据源类型设计

字段类型严格读取参数字典的 `sourceType`。不能根据单元格颜色、当前是否有值或字段名称自行推断。

| 类型 | 网站行为 | 是否进入计算 |
|---|---|---|
| 内部填写 | 普通输入框或下拉框，用户直接修改，可留空 | 使用 currentValue；空值传递为缺失状态，不得静默变 0 |
| 自动爬虫 | 输入框显示灰色 suggestedValue，提供采用按钮和来源入口 | 灰色提示不参与；采用或手工填写后使用 currentValue |
| 公式自动 | 只读结果框，展示原公式和依赖字段（B12 为只读常量 5000） | 只使用公式计算结果；B12 缺省时用默认值补齐 |

当前参数字典字段数量为 75 个，仅三类来源：内部填写 49 个、自动爬虫 20 个、公式自动 6 个。原 `暗访实地`（S1/S2/S6/S7）与 `市场调研`（E4）已统一并入 `内部填写` —— 它们本就同属业务人员手工录入，分开标注只会造成页面分组割裂。

## 4 自动爬虫建议值交互

政策来源抓取和解析完成后，不直接覆盖城市参数。系统为每个可匹配字段保存：

- `currentValue`：当前真正参与计算的值。
- `suggestedValue`：爬虫或解析器生成的建议值。
- `suggestedSource`：来源名称、URL、原文 ID 和原文位置。
- `suggestedAt`：建议值生成时间。
- `valueState`：`empty`、`suggestion_ready`、`accepted` 或 `overridden`。

页面表现：

```text
常住总人口
[ 1000 ]        当前实际值
建议值：820 万人   来源：长沙市统计局  更新时间：2026-09-09
[采用建议值] [查看来源]
```

灰色文字是 placeholder 或辅助提示，不是实体输入值。用户点击“采用建议值”后，建议值才写入 currentValue。用户直接输入时，currentValue 变为手工值，状态为 overridden，最近一次建议值和来源继续保留。

## 5 公式自动交互

H 列标记为“公式自动”的字段不提供普通填写能力。页面展示公式结果、公式说明、依赖字段和“待业务确认”标签。需要变更时，应修改公式定义或公式默认系数，而不是在当前值输入框中覆盖。

第一版严格保留 Excel 现有行为。以下问题不自动修正：

- `S5 站点覆盖失能客户上限` 的原公式最后一项引用 `E12`，与字段含义存在疑似引用问题。
- `S3 护理员日工作时段` 的原公式结果与“小时”单位存在疑似不一致。
- `B12 GR公关月均费用` 在 H 列标记为公式自动，但 E47 当前是固定数值 5000，不是 Excel 公式。

## 6 政策资料自动采集

政策资料是城市测算的数据来源服务，不是手动上传资料管理系统。Demo 不提供前端手动上传入口。用户配置公开政策官网 URL 后，点击“一键抓取”：

```text
官网 URL
  → Python 抓取
  → 保存 HTML、PDF 或公开附件原文
  → 生成 SHA-256 指纹和抓取历史
  → 提取标题、日期、城市、政策条款和参数建议值
  → 关联 Excel 参数编号
  → 在城市测算页显示灰色建议值
  → 用户采用或手工覆盖
```

每条原始资料必须保留来源 URL、最终 URL、抓取时间、HTTP 状态、内容类型、文件大小、内容指纹和本地相对路径。相同内容不重复保存文件实体，但保留本次抓取记录。抓取失败不得删除上一次成功资料。

## 7 计算与同步

后端使用确定性 Python 计算引擎复刻 Excel：

1. 读取城市字段 currentValue。
2. 对缺失值、真实 0 和不适用分别处理。
3. 生成筹备期、启动期和平台期的 24 个月序列。
4. 计算客户、收入、变动成本、固定成本、利润和现金流。
5. 输出核心指标、月度投影和阶段汇总。
6. 保存输入快照、结果快照、模型版本和问题列表。
7. 把城市最新有效结果同步到全局仪表盘。

政策建议值只有在用户采用后才更新 currentValue。参数变更后场景标记为待重算，旧结果可以继续展示，但不能伪装成新参数对应的结果。

## 8 本地数据模型

SQLite 保存城市、字段定义、字段值、公式定义、政策来源、抓取记录、原始资料和测算结果。核心表：

- `cities`
- `field_definitions`
- `field_values`
- `formula_definitions`
- `data_sources`
- `crawl_artifacts`
- `policy_suggestions`
- `calculation_snapshots`

原始政策资料保存在本地文件目录，数据库只保存文件 ID、相对路径、类型、大小、指纹和状态。所有导出通过记录 ID 定位，不允许前端提交任意本地路径。

## 9 Demo 验收标准

- 根路径直接打开全部城市总览，不要求登录。
- 所有人可以查看和修改 Demo 数据。
- 新增城市后，可以按 Excel 控制台 75 个字段配置并运行测算。
- 自动爬虫字段可以显示灰色建议值，建议值不参与计算。
- 点击采用后建议值成为真实参数，手工输入可覆盖并留存来源。
- 公式自动字段不能在普通输入框修改。
- 公式疑点原样保留并显示“待业务确认”。
- 抓取原文和附件本地保存，可以下载和导出。
- 首页可以按全部城市、单城市和多城市切换，并同步最新测算结果。
- Demo 不包含登录、权限、审批、生产级安全承诺和个人敏感数据。
