## 实施摘要

- 后端：`ProjectRepository` 协议 + `SqliteProjectRepository` / `JsonProjectRepository` 新增 `delete_project`；`DELETE /api/projects/{project_id}`（404 走 `NOT_FOUND` 稳定结构）。
- 级联顺序（显式，因 `calculation_snapshots` / `scenario_field_value_history` 无外键）：history → values → snapshots → scenarios → projects。
- 实测：删除后 4 张关联表行数为 0，`PRAGMA foreign_key_check` 为空，无孤儿行；`data_sources`/`crawl_artifacts` 按城市保留。
- 前端：`packages/ui` 新增 `alert-dialog.tsx`（基于 `@radix-ui/react-alert-dialog`）；根布局挂载 Sonner `Toaster`；列表页与详情页均有删除入口 + 确认框（列出删除范围）。

**需求二（总览改版）**
- 筛选区城市选择由多选下拉改为**复选框组**，含全选前 5 / 清除选择 / 超限提示；`scope` 由勾选数量推导（0 或 >5 → global，1 → city，2–5 → compare）。
- 三种视图：全城对比（原口径）、单城市分析（新 `city-focus-panel.tsx`）、多城对比。
- 单城市分析新增：中位数定位指标卡、月度趋势、成本结构饼图、中位数横向对比、回本周期分布、数据完整度与风险对比、**政策信息提炼区**（来源/抓取/待审核/已采用）。
- 城市复选框选项按**全量口径**独立拉取，避免勾选后筛选响应丢失其他可选项。
- 新增前端测试：视图路由/中位数/成本结构纯函数 6 个，复选框联动 3 个，单城市政策区渲染 1 个。

**踩坑记录**
- nuqs `parseAsArrayOf` 默认是**逗号分隔单键**（`cityIds=a,b`），不是重复键（`cityIds=a&cityIds=b`）。手写重复键 URL 只会解析出第一个。
- 列表接口返回的 `scenario.calculatedAt` / `resultSnapshotId` 可能为空但 `result` 存在且状态为 `calculated`，统计「已算出结果的场景」需同时判断 `result` 与 `status`。

## 需求一：项目 / 城市删除功能

### 现状

- 全链路只有新增：后端 0 个 `DELETE` 路由，两个仓储（SQLite / JSON）均无 `delete_*` 方法，前端无任何删除入口。
- 数据模型说明：**「城市测算对象」= project**（`city` 只是 project 的属性，一个项目即一座城市），城市列表页就是项目列表页，因此「删除城市」与「删除项目」是同一操作。

### 需求要点

1. **删除入口（前端）**
   - 城市列表卡片：新增「删除」按钮（危险样式，与「打开城市」并排）。
   - 城市详情（城市测算工作台）：页头提供删除入口。
2. **删除前确认（防误删，PRD 4.4 不静默删除）**
   - 弹出确认框，明确列出删除范围：项目名称、城市、**场景数量**、将一并删除的**计算快照数量**、字段值与修改历史。
   - 需二次点击确认，不做「输入名称」等更重交互（Demo 阶段）。
   - 删除成功后 toast 提示并刷新列表；失败展示稳定错误信息。
3. **后端级联删除**
   - `DELETE /api/projects/{projectId}`：不存在返回 404 `NOT_FOUND`（PRD 16.8 结构）。
   - 级联范围：`scenarios` → `scenario_field_values`（外键可级联）+ `scenario_field_value_history`、`calculation_snapshots`（**这两张表无外键约束，必须显式删除**——测试数据清理时已验证过该顺序）。
   - 两个仓储实现同步补齐：`SqliteProjectRepository` 与 `JsonProjectRepository`（契约协议 `ProjectRepository` 增加 `delete_project`）。

### 改动范围

| 层 | 文件 | 改动 |
|---|---|---|
| 后端·仓储 | `services/api/app/sqlite_repository.py`、`repository.py` | 新增 `delete_project`（显式按序删 4 张关联表） |
| 后端·协议 | `services/api/app/repository.py` | `ProjectRepository` 协议加 `delete_project` |
| 后端·路由 | `services/api/app/api/routes.py` | 新增 `DELETE /projects/{project_id}` |
| 后端·测试 | `tests/` | 删除成功级联校验、404、删除后列表/仪表盘不再出现 |
| 前端·组件库 | `packages/ui` | **新增 `alert-dialog`（Radix）**——现有组件库无对话框，属必要新增（按 AGENTS.md 记录复用判断） |
| 前端·页面 | `projects/page.tsx`、`city-project-workbench.tsx` | 删除按钮 + 确认框 + 刷新/toast |

## 需求二：总览页改版

### 现状

- `DashboardOverview` 已有：筛选区（视图/城市/周期下拉 + nuqs URL 同步）、指标卡、经营趋势折线、月收入与月净利润柱状对比、城市比较区、政策与风险提醒列表。
- 已有可复用接口：`/api/dashboard/cities/{cityId}`（单城市摘要）、`/api/policies/cities/{cityId}`（单城市政策详情）、`/api/dashboard/policy-summary`。
- 筛选条件已进 URL（PRD 9.2），刷新保留。

### 需求要点

1. **默认视图 = 全部城市对比**：进入总览默认展示所有城市计算结果对比（现状口径保留：折线趋势 + 指标卡 + 柱状对比 + 城市比较 + 政策/风险提醒）。
2. **城市复选框切换**：筛选区城市选择改为**复选框组**（替代现有多选下拉）：
   - 不勾选 / 全勾 → 全城汇总对比视图；
   - 勾选 1 个 → 切换为**该城市分析视图**；
   - 勾选 2–5 个 → 多城对比视图（沿用 PRD 9.2 上限）。
   - 选择结果继续写入 URL（`cityIds`，nuqs 默认逗号分隔单键格式 `cityIds=a,b`），刷新/分享保留。
3. **单城市分析视图（新增）**：
   - 该城市核心指标卡（含与全体中位数的横向定位）、12/24 月营收/净利/累计现金流趋势；
   - 成本结构（照护师/销售/护士/固定）饼图拆解 + 占比列表；
   - 与全体城市中位数的横向对比（定位该城市水平）；
   - 补充图表：回本周期分布（全体口径）、数据完整度与风险计数对比；
   - **政策信息提炼区（单独展示）**：官网来源与最近抓取状态、待审核候选字段、已采用政策字段，数据取自 `/api/policies/cities/{cityId}`，与城市测算、政策资料页互通跳转。
4. **图表可自由规划并适当补充**：在现有视觉规范内（shadcn/ui + Recharts + 语义色变量），补充回本周期分布、城市数据完整度/风险计数对比、成本结构占比；金额展示遵守中文习惯（¥、千分位、不省略正负号）。
5. **口径澄清（已确认）**：「当前项目已创建的所有城市」= **已创建的全部城市测算对象**（全局聚合口径）。模型里「一个项目 = 一座城市」，不存在「项目下多城市」。
