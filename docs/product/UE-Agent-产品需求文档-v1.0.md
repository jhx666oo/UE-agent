## 1 产品概述

### 1.1 产品名称

UE Agent。

### 1.2 产品定位

UE Agent 是一个面向长护险城市成本测算的网页 Demo。网站以城市为核心对象，把 Excel UE 模型中的控制台参数、公式和结果映射为可视化页面。任何访问者都可以查看全部城市总览、切换单城市或多城市对比、修改参数、运行 24 个月测算，并查看结果如何同步到首页。

政策资料不是独立的资料管理系统，而是测算网站的数据来源服务。用户可以配置公开政策官网链接，一键触发 Python 爬虫，保存原始网页或附件，并把抓取结果以灰色建议值的形式提供给参数填写区域。Demo 暂不实现登录和权限控制，所有查看、编辑和抓取操作对访问者开放。

系统提供的是可复算、可追溯的经营分析依据，不替代业务负责人作出最终投资决策。

### 1.3 核心能力

| 能力 | 说明 |
|---|---|
| 全部城市总览 | 汇总已有城市的最新有效测算结果，展示收入、利润、现金流、投资和风险 |
| 单城市分析 | 查看指定城市的趋势、成本结构、关键参数、政策资料和待确认问题 |
| 多城市比较 | 选择多个城市，按统一口径比较经营指标和数据完整度 |
| 城市成本测算 | 为每个城市配置 Excel 控制台参数、运行 24 个月公式并保留结果快照 |
| 政策资料采集 | 配置公开官网来源，一键抓取最新网页或附件并保存原始文件 |
| 官网数据采集 | 通过本地 Python 程序抓取公开官网页面，保存原文、元数据和历史版本 |
| 政策解析 | 将抓取结果解析为与 Excel 参数编号关联的建议值，供用户采用或覆盖 |
| 数据导出 | 导出政策列表、抓取记录、结构化政策字段和原始资料 |
| 模型追溯 | 记录参数编号、Excel 单元格、公式版本和待业务确认问题 |

### 1.4 系统关系

```text
城市测算参数
  → 保存场景
  → Python 确定性计算引擎
  → 不可变结果快照
  → 总览仪表盘

政策官网数据源
  → 一键抓取原文或附件
  → 保存原始文件和历史版本
  → 解析政策内容和参数建议值
  → 灰色建议值展示
  → 用户采用或手动覆盖
  → 城市参数和仪表盘
```

## 2 项目背景

长护险业务进入一个新城市时，需要同时判断政策是否落地、适用人群有多大、服务单价和支付比例如何、护理站能够覆盖多少客户、人员配置是否满足政策要求，以及项目从筹备到稳定经营需要投入多少资金。

当前信息主要分散在政策文件、政府网站、调研材料、业务人员经验和 Excel 测算表中，存在以下问题：

- 同一指标可能同时存在官方值、历史值、估算值和人工确认值。
- 城市、区县和单个护理站的统计口径容易混用。
- Excel 参数和公式缺少统一版本，疑似公式问题不容易追踪。
- 每个城市单独测算后，缺少统一的全局比较页面。
- 政策官网内容更新后，缺少一键抓取、原文留存和参数建议值之间的关联。
- 政府官网内容可能更新，人工逐个检查耗时且难以保留历史版本。
- 修改参数后，旧结果可能继续被误认为当前有效结果。

UE Agent 将这些资料整理为统一的数据链路，并明确区分原始资料、自动采集建议值、用户实际填写值和计算结果。

## 3 产品目标

### 3.1 业务目标

1. 让访问者在网页中完成城市测算参数配置和测算，不再直接修改 Excel 公式。
2. 让管理者从首页查看全部城市的经营结果和差异。
3. 让每个结论可以追溯到参数、政策文件、官网来源和模型版本。
4. 让政策资料以官网自动采集为主，支持原始文件存储、建议值填充和导出。
5. 严格复刻当前 Excel 逻辑，疑似问题原样保留并标记为“待业务确认”。
6. 使用本地数据库和本地文件目录保存数据，避免业务资料依赖外部云数据库。

### 3.2 用户结果

完成一个城市测算后，用户应当能够回答：

- 当前城市采用的是哪一个测算场景和模型版本。
- 24 个月内客户、收入、成本、利润和现金流如何变化。
- 项目需要多少初始投资，最大资金缺口是多少。
- 项目何时达到月度盈亏平衡，累计现金流何时回正。
- 哪些参数来自政策或公开数据，哪些由业务人员手工填写。
- 哪些公式或数据仍存在疑问。
- 该城市与其他城市相比，市场规模、盈利能力和政策完备度处于什么水平。

### 3.3 成功标准

- 一个新城市可以在网页中完成城市创建、参数配置、测算和结果保存。
- API 重启后，项目、场景、测算结果和政策资料仍然存在。
- 首页可以自动读取全部城市的最新有效结果。
- 参数发生变化但尚未重算时，系统明确显示“待重算”。
- 爬虫建议值不会直接覆盖真实参数，也不会在用户未采用前参与计算。
- 官网抓取结果能够保存、预览、比较版本并导出。
- Excel 已登记疑点不会被程序自动修正或隐藏。

## 4 产品原则

### 4.1 确定性计算

收入、成本、利润、现金流等核心结果必须由 Python 公式引擎计算。前端只负责参数输入和结果展示，大模型不得直接生成核心财务数值。

### 4.2 数据来源可追溯

参考数据至少记录来源名称、原始链接或文件、适用城市、统计时间、抓取或上传时间、审核状态和更新时间。

### 4.3 建议值不等于实际值

官网抓取和机器提取先生成建议值。建议值以输入框灰色占位文字展示，不写入真实参数，也不参与计算。用户可以点击“采用建议值”，也可以直接手工填写或覆盖。系统必须保留建议值的来源、采集时间和原始文件。

### 4.4 不静默覆盖

政策字段更新或参考数据变化时，系统只能提示用户应用新值，不能在后台自动覆盖已保存的项目输入。

### 4.5 状态必须明确

系统必须区分缺失值、真实零值、不适用、公式错误、待审核、已过期、待重算和计算失败。未知数据不得显示为 0。

### 4.6 Excel 原样复刻

当前模型以 Excel 公式为第一版复刻基准。发现疑似引用错误、数量级异常或除零错误时，第一版保留原行为并附带问题标记。业务确认后的修正通过新模型版本发布，不改写历史结果。

## 5 用户与使用场景

### 5.1 业务人员

主要任务：新增城市、填写参数、运行测算、查看结果、比较城市。

### 5.2 城市负责人

主要任务：确认本地政策、经营假设和测算结果，处理待业务确认事项。

### 5.3 政策资料使用者

主要任务：配置官网来源、执行一键抓取、查看原文、采用或修改政策建议值。

### 5.4 模型维护人员

主要任务：维护参数字典、公式台账、模型版本、回归样例和问题目录。

### 5.5 管理人员

主要任务：查看全部城市总览、经营趋势、多城市对比和风险提醒。

### 5.6 Demo 权限范围

Demo 阶段不实现登录页、账号体系、角色权限和审批流。所有访问者都可以查看结果、修改城市参数、新增城市、配置政策来源、触发抓取和导出数据。页面必须明确显示“Demo 数据”，不得把这一模式当作生产环境安全方案。

## 6 产品范围

### 6.1 本版本包含

- 全部城市总览仪表盘。
- 单城市视图和多城市对比。
- 城市创建、编辑和列表管理。
- 多场景保存、复制、测算和结果快照。
- 24 个月 U1 测算结果展示。
- 政策资料全局总览和城市详情。
- 固定官网链接配置和前端一键抓取。
- 抓取历史、原文保存、内容指纹和状态记录。
- 爬取结果解析、灰色建议值、一键采用和手工覆盖。
- CSV、JSON 和原始文件导出。
- 本地 SQLite 数据库存储。
- 参数字典、公式台账和已知问题展示。

### 6.2 本版本不包含

- 自动作出城市投资结论。
- 自动修改或发布未经业务确认的 Excel 公式。
- 自动提交长护险定点机构申报。
- 老人订单、护理排班和实际履约管理。
- 全国政府网站的无限递归爬取。
- 绕过登录、验证码、反爬措施或访问控制。
- 爬虫建议值未经用户采用直接覆盖项目参数。
- 复杂地图路径规划和实时调度。
- 多租户、企业级账号权限和审批流。
- 手机原生应用。

## 7 信息架构

### 7.1 主导航

左侧主导航固定为四个入口：

1. 总览。
2. 城市测算。
3. 政策资料。
4. 城市对比。

“工作台”“项目管理”和“U1 城市选址”不再作为主导航入口。字段与公式不单独作为系统管理页面，字段说明和公式说明放在城市测算页面内。旧地址可以保留兼容跳转，但用户看到的产品名称统一为“城市测算”。

### 7.2 页面结构

| 一级页面 | 二级页面 | 主要职责 |
|---|---|---|
| 总览 | 全部城市 | 汇总所有有效城市结果和风险 |
| 总览 | 单城市 | 展示指定城市的趋势、结构和政策影响 |
| 总览 | 多城市对比 | 按统一维度比较选中的城市 |
| 城市测算 | 城市列表 | 查看城市状态、最新测算和待处理事项 |
| 城市测算 | 新增城市 | 建立城市和初始测算参数 |
| 城市测算 | 城市详情 | 配置参数、运行测算、查看结果 |
| 政策资料 | 政策总览 | 查看各城市资料和数据源状态 |
| 政策资料 | 城市政策详情 | 查看原文、官网来源、抓取记录和参数建议值 |
| 城市测算 | 公式说明 | 查看 Excel 参数编号、公式版本和待确认问题 |

### 7.3 默认入口

访问系统根路径时直接进入“全部城市总览”。若系统尚无有效城市结果，首页显示空状态并引导新增城市。Demo 不要求登录，访问者可以直接进入所有页面。

## 8 核心业务流程

### 8.1 城市测算流程

```text
新增城市
  → 建立测算场景
  → 配置参数
  → 保存草稿
  → 运行测算
  → 生成结果快照
  → 复核结果和问题
  → 确认结果
  → 同步到总览仪表盘
```

### 8.2 政策文件流程

```text
选择城市
  → 配置政策官网链接
  → 一键抓取
  → 保存网页、PDF 或附件原文
  → 解析政策内容和参数建议值
  → 在参数输入框显示灰色建议值
  → 用户采用建议值或手工覆盖
  → 更新城市测算参数
```

### 8.3 官网抓取流程

```text
配置固定官网来源
  → 点击立即抓取
  → 校验网址和访问范围
  → 下载原始响应
  → 保存网页或附件
  → 生成内容指纹
  → 提取标题和可读文本
  → 生成抓取记录
  → 生成政策参数建议值
  → 用户选择采用或修改
```

### 8.4 政策字段应用流程

```text
政策建议值
  → 以灰色占位文字展示
  → 用户点击采用建议值
  → 转为真实参数值
  → 项目参数更新并标记待重算
  ↘ 用户手工填写
  → 标记为手工覆盖并保留建议值来源
```

## 9 总览仪表盘

### 9.1 功能概述

总览仪表盘是城市成本测算网站首页，用于查看已有城市的经营测算结果、趋势、成本结构、政策状态和待处理风险。Demo 阶段页面不做权限限制，参数修改通过城市测算页面完成，所有访问者都可以进入和修改。

### 9.2 视图切换

页面顶部支持以下范围：

- 全部城市：汇总所有有有效结果的城市。
- 单个城市：查看一个城市的完整经营摘要。
- 多城市对比：选择 2 至 5 个城市进行比较。

筛选条件至少包括城市范围、12 或 24 个月周期、是否包含待重算结果。页面刷新后应保留当前 URL 中的筛选条件。

### 9.3 全部城市核心指标

顶部指标卡展示：

| 指标 | 口径 |
|---|---|
| 有效城市数 | 至少存在一条 calculated 或 confirmed 快照的城市数量 |
| 目标客户规模 | 各城市最新有效快照的目标客户数合计 |
| 预计月收入 | 各城市平台期月收入合计 |
| 预计月净利润 | 各城市平台期月净利润合计 |
| 总初始投资 | 各城市初始投资合计 |
| 回本周期中位数 | 有回本月份城市的投资回收期中位数 |
| 待业务确认数 | 公式问题、政策建议值、过期数据和待重算事项总数 |

没有有效结果的城市不参与金额和客户合计，但仍出现在城市状态列表中。

### 9.4 经营趋势

主趋势图展示 12 或 24 个月的：

- 总收入。
- 总成本。
- 总净利润。
- 累计现金流。

全部城市视图默认展示合计曲线。用户可以突出最多 5 个城市的单独曲线。图例、坐标轴和提示框必须显示单位，金额不得省略正负号。

### 9.5 城市比较

城市比较区域包括：

- 市场规模与回本周期散点图。
- 初始投资与 24 个月累计净利润条形图。
- 平台期收入、成本和净利润对比。
- 成本结构对比。
- 数据完整度、政策资料状态和待确认问题数。

首版不生成综合城市评分，不使用未经业务确认的权重把不同量纲压缩为一个分数。

### 9.6 政策和风险提醒

提醒列表至少包含：

- 参数已修改但尚未重新测算。
- 城市没有有效测算结果。
- 政策资料缺失或已过期。
- 官网来源最近抓取失败。
- 有新的抓取版本待查看。
- 政策建议值待采用。
- Excel 疑似公式问题。
- 计算结果存在公式错误或数量级异常。

每条提醒必须显示城市、类型、产生时间和下一步入口。

### 9.7 单城市视图

单城市页面展示：

1. 城市、区县、当前场景、模型版本和最近测算时间。
2. 收入、成本、利润和累计现金流趋势。
3. 初始投资、最大资金缺口、回本月份和平台期净利润。
4. 成本结构拆解。
5. 客户规模和人员需求变化。
6. 关键参数摘要及来源。
7. 已抓取政策资料和参数建议值。
8. 待业务确认问题。
9. 进入城市测算和政策资料的入口。

### 9.8 仪表盘验收要点

- 新增城市并完成测算后，无需在前端重复录入结果即可出现在首页。
- 全局金额等于纳入城市最新有效快照的同口径合计。
- 切换城市后，所有指标卡、图表和提醒使用同一范围。
- 数据缺失时显示“暂无数据”，不得显示伪造图形或默认零值。

## 10 城市测算

### 10.1 功能概述

城市测算用于维护一个城市的业务参数、测算场景和结果。当前产品规则为“一座城市对应一个主测算对象”，对象内部可以建立多个独立场景。页面名称、按钮和提示统一使用“城市测算”，不使用“项目管理”表达。

### 10.2 城市列表

列表字段包括：

| 字段 | 说明 |
|---|---|
| 城市 | 城市名称和测算对象 |
| 行政区 | 当前测算适用区县 |
| 当前场景 | 最近使用的场景名称 |
| 模型版本 | 结果所使用的公式版本 |
| 测算状态 | 草稿、待重算、计算中、已计算、已确认、失败 |
| 最近测算时间 | 最新有效快照产生时间 |
| 回本周期 | 最新有效快照的回本月份 |
| 平台期月净利润 | 最新有效快照的平台期结果 |
| 数据完整度 | 必填参数、来源和确认状态的完成情况 |
| 待确认问题 | 当前项目关联的问题数量 |

支持打开城市、新增城市、复制场景、运行测算和查看结果。Demo 阶段所有访问者都可以执行这些操作。归档和删除属于后续能力，首版不得直接永久删除已有结果快照。

### 10.3 新增城市

必填信息包括：

- 省份、城市和区县。
- 站点模式：自营、收购、联营或其他。
- 初始场景名称。
- 使用的模型版本。

同一城市已经存在测算对象时，系统应提示用户进入已有城市或明确创建独立对象，不允许无提示地生成重复城市记录。

### 10.4 项目详情

页面顶部显示城市、区县、站点模式、当前场景、模型版本、最近测算时间和状态。

参数按业务分组展示：

1. 城市与市场。
2. 政策准入。
3. 站点空间。
4. 成本参数。
5. 阶段参数。
6. 效率与风险。
7. 辅助收入。
8. 战略情景。

每个参数必须显示 Excel 编号、参数名称、单位、当前值、数据源类型、建议值状态、来源、采集时间和问题标记。字段顺序以 `控制台` 工作表为准，页面不得把全部字段堆成无分组长表。

### 10.5 参数编辑

- 数字、比例、金额、月份和枚举参数使用对应控件。
- 比例在界面中按百分比展示，存储和计算统一使用 0 至 1。
- `内部填写`字段使用正常可编辑输入框，允许保存真实数值 0。
- `自动爬虫`字段在没有实际值时显示灰色建议值。建议值不是实体值，不参与计算，也不写入当前参数。
- 用户点击“采用建议值”后，建议值才写入当前参数；用户也可以直接手工输入并标记为“已手动覆盖”。
- `公式自动`字段为只读结果，不提供普通填写框。需要调整时进入公式默认值配置，不直接修改结果值。
- `内部填写`字段允许手动填写或留空（原 `暗访实地`、`市场调研` 已统一并入该类）。
- 参数发生变化后，当前场景标记为 `stale`，旧结果保留但不作为新参数的计算结果。

### 10.6 场景管理

每个项目至少有一个场景。用户可以：

- 新建空白场景。
- 复制已有场景。
- 修改场景名称。
- 保存草稿。
- 执行测算。
- 查看历史结果。
- 确认某次结果。

场景复制后独立保存，后续修改不得影响来源场景。

### 10.7 场景状态

```text
draft → stale → calculating → calculated → confirmed
                         ↘ failed
```

| 状态 | 含义 |
|---|---|
| draft | 新场景或尚未完成必要参数 |
| stale | 参数在最近一次测算后发生变化 |
| calculating | 计算正在执行 |
| calculated | 结果与当前输入一致 |
| confirmed | 用户已确认本次结果 |
| failed | 参数校验或公式执行失败 |

### 10.8 测算执行

点击“运行测算”后，后端必须：

1. 校验必填参数和数据类型。
2. 保留空值、真实零值和不适用状态。
3. 调用指定模型版本的 Python 计算函数。
4. 生成 24 个月结果。
5. 收集公式错误和待确认问题。
6. 保存输入快照、结果快照和模型版本。
7. 返回本次计算状态。

一次成功测算生成一条不可变快照。重新测算只能新增快照，不能覆盖历史结果。

### 10.9 结果复核

结果页顶部展示：

- 投资回收期。
- 最大资金缺口。
- 月度盈亏平衡月份。
- 24 个月累计净利润。
- 24 个月期末累计现金流。
- 平台期月均收入和净利润。
- 盈亏平衡客户数。

下方展示客户爬坡、收入成本利润趋势、累计现金流、人员需求、成本结构、阶段摘要、参数快照、月度明细和问题清单。

### 10.10 项目同步规则

- `calculated` 和 `confirmed` 快照可以进入仪表盘。
- 一个城市默认只使用 `calculatedAt` 最新的有效快照。
- 参数修改后，仪表盘保留上一条有效结果，同时标记“待重算”。
- 失败结果不得覆盖上一条有效结果。
- 快照必须保存场景名称、完整输入、完整结果、模型版本和问题列表。

## 11 政策资料

### 11.1 功能概述

政策资料页面是城市测算网站的数据来源中心，集中展示城市政策官网来源、自动抓取结果、原始文件、解析内容和参数建议值。页面支持“全部城市”和“单城市”两种查看范围。首版不以人工上传资料为主。

### 11.2 政策总览

总览字段包括：

| 字段 | 说明 |
|---|---|
| 城市 | 政策适用城市 |
| 数据源数量 | 当前配置的政策官网来源数量 |
| 数据源状态 | 正常、停用、最近失败或从未抓取 |
| 文件数量 | 已抓取并保存的网页、PDF 或附件数量 |
| 建议值数量 | 已解析但尚未被用户采用的参数建议值数量 |
| 已采用数量 | 用户已写入城市参数的建议值数量 |
| 最近更新时间 | 最近抓取、解析或采用时间 |
| 风险状态 | 缺失、过期、抓取失败或存在变更 |

支持按城市、来源状态、审核状态和更新时间筛选。

### 11.3 城市政策详情

城市详情由四个区域组成：

1. 政策摘要。
2. 自动采集文件。
3. 官网来源与抓取记录。
4. 参数建议值和使用记录。

政策摘要至少覆盖服务对象、服务单价、基金支付比例、个人支付比例、服务时长、待遇上限、机构准入、人员配置、场地设备要求、政策生效时间和来源。

### 11.4 自动采集原始资料

政策原始资料由官网抓取产生。抓取到 HTML、PDF 或公开附件后，系统必须先保存原始内容，再进行解析。保存字段包括：

- 原始标题和文件名。
- 系统文件 ID。
- 所属城市和来源 ID。
- 文件大小和内容类型。
- 抓取时间。
- SHA-256 内容指纹。
- 当前处理状态。
- 原始文件本地相对路径。

单个响应默认上限为 20 MB。相同来源、相同内容指纹重复抓取时保留抓取记录，但不重复保存文件实体。Demo 不设置前端手动上传入口；后续如确有离线资料需求，再单独增加导入能力。

### 11.5 官网来源配置

用户可以在前端新增和编辑固定官网来源。配置字段包括：

| 字段 | 必填 | 说明 |
|---|---|---|
| 来源名称 | 是 | 便于业务识别的名称 |
| 所属城市 | 是 | 数据适用城市 |
| 来源类型 | 是 | 政府官网、政策栏目、通知公告或直接文件 |
| 官网链接 | 是 | 公开 HTTP 或 HTTPS 地址 |
| 启用状态 | 是 | 启用或停用 |
| 请求超时 | 否 | 默认 15 秒，最大 60 秒 |
| 最大文件大小 | 否 | 默认 10 MB，最大 20 MB |
| 备注 | 否 | 记录栏目范围、关键词或人工说明 |

来源列表显示最近抓取时间、最近状态、最近 HTTP 状态码、是否发现内容变化和操作按钮。

### 11.6 一键抓取

点击“立即抓取”后，后端 Python 抓取程序执行以下动作：

1. 校验来源存在且处于启用状态。
2. 校验 URL 协议和目标地址。
3. 以 GET 请求访问公开页面。
4. 最多跟随 5 次重定向，并重新校验目标地址。
5. 按配置执行超时和响应大小限制。
6. 保存原始响应内容。
7. 计算 SHA-256 内容指纹。
8. 对 HTML 提取页面标题、可读文本和页面链接。
9. 写入抓取记录并更新来源状态。
10. 与上一次成功记录比较，标记“无变化”或“发现新版本”。

首版只抓取用户配置的单个 URL，不自动递归抓取整个网站。HTML 页面中发现的公开附件链接可以展示出来，由用户选择后继续抓取并保存。每次抓取完成后都要生成参数建议值，不直接覆盖城市实际参数。

### 11.7 抓取安全限制

- 只允许 HTTP 和 HTTPS。
- 默认阻止本机回环地址、链路本地地址和私有网段。
- 不提交登录表单，不携带个人账号 Cookie。
- 不绕过验证码、登录、付费墙或其他访问限制。
- 使用可识别的 User-Agent。
- 单个来源同一时间只允许一个抓取任务。
- 抓取失败不删除上一次成功结果。
- 遵守公开网站的 robots 和合理访问频率。

### 11.8 抓取记录

每次抓取保存：

| 字段 | 说明 |
|---|---|
| artifactId | 抓取记录唯一标识 |
| sourceId | 来源标识 |
| cityId | 所属城市 |
| requestedUrl | 用户配置的地址 |
| finalUrl | 重定向后的最终地址 |
| fetchedAt | 抓取时间 |
| httpStatus | HTTP 状态码 |
| contentType | 内容类型 |
| contentLength | 实际保存大小 |
| sha256 | 内容指纹 |
| storedPath | 本地原始文件位置 |
| title | 页面或文件标题 |
| changeStatus | 首次抓取、无变化或发现新版本 |
| status | 成功或失败 |
| errorMessage | 失败原因，不包含敏感信息 |

原始抓取文件保存在 `services/api/data/raw_sources/`。历史记录不可被新抓取覆盖。

### 11.9 原文预览

- HTML 显示提取后的纯文本预览，并提供查看原始文件入口。
- 抓取到的 PDF、Word 和 Excel 附件显示文件基本信息和下载入口。
- 预览页必须显示来源 URL、抓取时间和内容指纹。
- 原始 HTML 不直接以可执行方式嵌入页面，避免脚本运行。

### 11.10 政策参数建议值

自动解析的政策信息至少包括：

- 文件标题和文号。
- 发布机关。
- 发布日期、生效日期和失效日期。
- 适用省、市和区县。
- 服务对象范围。
- 服务单价。
- 基金和个人支付比例。
- 服务频次、服务时长和待遇上限。
- 定点机构准入要求。
- 人员数量和资质要求。
- 场地、设备和信息系统要求。
- 申报材料要求。

每个建议值必须关联原始文件或抓取记录，并保留原文摘录、页面位置或页码说明。没有可靠来源位置时，只能作为文本提示，不能进入可采用建议值列表。

### 11.11 建议值状态

政策资料状态如下：

```text
fetched
  → parsed
  → suggestion_ready
  → accepted 或 overridden
  ↘ failed
```

- `fetched`：官网内容已抓取并保存原文。
- `parsed`：已提取标题、正文和结构化内容。
- `suggestion_ready`：已生成与 Excel 参数编号关联的建议值。
- `accepted`：用户点击“采用建议值”，写入当前城市参数。
- `overridden`：用户手工填写，覆盖或替代建议值。
- `failed`：抓取或解析失败，并保留失败原因。

建议值默认不覆盖当前城市参数。采用或手工覆盖后，系统必须记录原始建议值、来源、操作时间和当前实际值。政策摘要可以直接展示已抓取的原文和解析内容，并明确标注数据状态。

### 11.12 政策数据导出

政策资料支持以下导出：

| 格式 | 内容 | 使用场景 |
|---|---|---|
| CSV | 政策来源、抓取记录或结构化政策字段 | Excel 查看和业务分析 |
| JSON | 完整元数据、状态、来源关系和结构化字段 | 数据迁移和程序处理 |
| ZIP | 原始抓取文件、解析结果和导出清单 | 原始资料归档 |

导出范围支持全部城市、单城市、指定来源和指定时间段。建议值、实际值和手工覆盖值必须分列导出，并附带来源、采集时间和状态，不能混合为一个无来源的参数值。

### 11.13 定时抓取

首版以前端手动“立即抓取”为主。数据模型保留抓取频率和下次执行时间字段，后续可以增加本地定时任务。定时抓取仍然只产生原文和建议值，不自动覆盖城市实际参数。

## 12 字段与公式

### 12.1 功能概述

字段与公式不再作为独立的系统管理模块。城市测算页面直接展示 Excel 控制台字段，公式说明和待确认问题放在同一页面的可展开区域。Demo 阶段所有访问者都可以查看和修改普通输入字段，但公式自动字段仍然只读。

### 12.2 数据源类型与控件规则

字段数据源类型严格读取参数字典的 `sourceType`，不得根据颜色、字段名称或是否存在当前值自行推断。全表仅三类，网站统一使用以下交互：

| 数据源类型 | 网站控件 | 计算规则 |
|---|---|---|
| 内部填写 | 正常可编辑输入框或下拉框 | 由业务人员自行录入；使用用户当前填写值，允许留空，允许真实 0；空值不得静默变成 0 |
| 自动爬虫 | 可编辑输入框 + 灰色建议值 + “采用建议值” | 灰字建议值不存储、不参与计算；采用后才成为当前值，用户也可直接改成自己的值 |
| 公式自动 | 只读结果框 + “公式”徽标 | 只能由公式计算；不得在普通填写框修改（B12 为只读常量，见 12.2.1） |

`暗访实地`、`市场调研` 等标签已统一并入 `内部填写`。这三类字段原本都由业务人员在网页上手工录入，分开标注只会让同一类字段在页面上落入不同视觉分组，因此统一名称为「内部填写」，存储与计算逻辑不受影响。

#### 12.2.1 B12 GR公关月均费用（只读常量）

B12 在 Excel 控制台 `E47` 中填的是固定值 5000，既非公式也无外部来源，但它同时被打上「公式自动」标签并列为必填，导致场景未预填时用户既无法填写、测算也永远无法通过。现明确定义为**只读常量默认值 5000**：参数字典 `required: false` 且带 `defaultValue: 5000`；引擎在计算前用默认值补齐缺省，缺省不再阻塞测算，用户显式给值仍然优先。

自动爬虫字段同时保存四个值：`currentValue`、`suggestedValue`、`suggestedSource` 和 `valueState`。当用户手工输入时，状态为 `overridden`；当用户采用灰色建议值时，状态为 `accepted`。每次采用或覆盖都保留历史记录。

## 14 U1 测算规则

### 14.1 参数分组

| 分组 | 编号范围 | 内容 |
|---|---|---|
| 城市与市场 | C1 至 C13 | 人口、年龄结构、失能率、医保和面积 |
| 政策准入 | P1 至 P11 | 服务单价、支付比例、最低人员和服务时长 |
| 站点空间 | S1 至 S8 | 覆盖半径、工作日、面积、租金和覆盖率 |
| 成本参数 | B1 至 B16 | 人员、系统、合规、装修、物料和初始投资 |
| 阶段参数 | D1 至 D8 | 筹备期、启动期、平台期和爬坡假设 |
| 效率与风险 | E1 至 E8 | 利用率、流失、提成、回款和坏账 |
| 辅助收入 | A1 至 A6 | 辅具、消费券、亲情照护和政府购买服务 |
| 战略情景 | Z1 至 Z5 | 自营、收购、联营和资源复用 |

### 14.2 字段值参与计算规则

1. `内部填写`字段使用 `currentValue`（含原 `暗访实地`、`市场调研` 字段）。
2. `自动爬虫`字段只有在用户点击“采用建议值”或手工输入后，才使用 `currentValue`。`suggestedValue` 仅作为灰色提示。
3. `公式自动`字段不读取普通输入框，按 `FormulaDefinition` 和 Excel 对应单元格计算。B12 为只读常量 5000，缺省时由引擎默认值补齐，不阻塞测算。
4. 真实 0、空值、不可用和公式错误必须分别编码，不能统一转换为 0。

### 14.3 计算顺序

1. 解析并校验参数，不将缺失值转为零。
2. 生成筹备期、启动期和平台期的 24 个月阶段序列。
3. 计算站点覆盖和目标客户规模。
4. 计算单客收入、基金收入、个人收入和辅助收入。
5. 计算护理员、销售和护士等变动成本。
6. 计算管理、租金、系统、培训、物料和合规等固定成本。
7. 计算毛利润、净利润、累计净利润和累计现金流。
8. 计算现金流回正月份和平台期盈亏平衡客户数。
9. 汇总阶段结果并附带问题列表。

### 14.4 结果状态

计算引擎返回：

- `calculated`：计算成功且无已登记问题。
- `calculated_with_issues`：计算成功，但包含待确认问题。
- `blocked`：必要输入缺失或非法。
- `formula_error`：公式产生除零或其他明确错误。

### 14.5 月度结果

每个月至少保存月份、阶段、客户数、单客收入、总收入、变动成本、固定成本、毛利润、净利润、累计净利润、累计现金流、回正标记和盈亏平衡客户数。

## 15 数据同步规则

### 15.1 项目到仪表盘

| 触发动作 | 仪表盘行为 |
|---|---|
| 保存草稿 | 不改变正式汇总 |
| 参数修改 | 保留上一条有效结果并标记待重算 |
| 测算成功 | 新快照成为该城市最新有效结果 |
| 测算失败 | 保留上一条有效结果并显示失败提醒 |
| 确认结果 | 快照状态更新为 confirmed |

### 15.2 政策到仪表盘

| 政策状态 | 仪表盘行为 |
|---|---|
| fetched | 计入资料数量，保留原文和来源 |
| parsed | 计入已解析资料数量 |
| suggestion_ready | 计入建议值数量，并显示“待采用”提醒 |
| accepted | 计入已采用建议值，可参与对应城市测算 |
| overridden | 计入手工覆盖记录，保留爬虫建议值来源 |
| failed | 显示抓取或解析失败，不覆盖已有参数 |

### 15.3 政策到项目参数

政策建议值可以显示为参数参考值。用户点击“采用建议值”后，系统把 `suggestedValue` 写入 `currentValue`，记录政策原文 ID、来源、原值、使用时间和状态，并将场景标记为 `stale`。用户直接手工填写时，不删除建议值，只把 `valueState` 标记为 `overridden`。

## 17 页面与交互规范

### 17.1 视觉方向

界面使用暖灰白背景、白色卡片、深石板文字和深青绿色主色。风险使用琥珀色，阻断错误使用红色。页面以指标卡、表格、表单和趋势图为主，不使用大面积渐变和无业务意义的装饰动画。

### 17.2 字体和按钮

- 中文正文优先使用系统无衬线字体。
- 按钮文字与正文使用同一字体体系和字重，不使用突兀的超粗字。
- 主按钮使用深青绿色底色和白色文字。
- 次按钮使用白色背景、浅灰边框和深色文字。
- 危险操作使用红色文字或红色边框，不与普通主按钮混用。
- 同一操作在不同页面使用统一名称，例如统一使用“运行测算”，不混用“开始计算”和“立即测算”。

### 17.3 字段输入交互

城市测算页面每一行参数统一显示：编号、参数名称、单位、输入控件、数据源标签和状态。不同数据源必须使用可区分但克制的视觉样式：

- `内部填写`：正常黑色输入值，标签显示“内部填写”。
- `自动爬虫`：真实当前值使用正常文字；建议值以浅灰色占位文字展示，旁边提供“采用建议值”和“查看来源”。灰色文字不得被当成输入值提交。
- `公式自动`：使用浅绿色只读结果框，显示公式图标和“查看公式”，不出现可编辑光标。B12 亦为只读，但其值为常量默认 5000。

采用建议值后，输入框中的值切换为实体值，建议来源变成辅助信息。用户手工修改后显示“已手动覆盖”，并保留最近一次建议值。所有操作对 Demo 访问者开放。

### 17.4 页面状态

每个数据模块必须设计：

- 加载中。
- 空数据。
- 部分数据。
- 数据过期。
- 操作成功。
- 操作失败。
- 建议值待采用。
- 建议值已采用。
- 手工覆盖。
- 公式问题待确认。

### 17.5 响应式规则

- 桌面端使用 12 列网格。
- 平板端图表按两列或单列排列。
- 手机端图表单列，指标卡可横向滚动。
- 多城市对比表在窄屏下改为可展开城市卡片。
- 风险提醒不得因为屏幕变窄而隐藏。

### 17.6 可解释性

指标卡和图表应提供口径提示。用户应当能够从仪表盘跳转到城市结果快照，从政策字段跳转到原始文件或抓取记录。

## 18 本地数据与运行模式

### 18.1 技术结构

```text
浏览器
  → Next.js 前端
  → FastAPI 后端
  → Python U1 计算引擎
  → SQLite 本地数据库
  → policy_files 和 raw_sources 本地文件目录
```

### 18.2 数据目录

```text
services/api/data/
├── ue-agent.sqlite3
├── policy_artifacts/
└── raw_sources/
```

SQLite 保存结构化数据；政策原文、抓取到的 PDF 和公开附件保存到本地文件目录；数据库中记录文件 ID、相对路径、内容指纹和元数据。Demo 不提供政策资料手动上传入口。

### 18.3 初始化

系统提供初始化命令，用于创建数据目录、数据库和表结构。重复执行初始化不得覆盖已有业务数据，也不得重复导入记录。

### 18.4 数据备份

系统提供手动备份能力，将 SQLite 文件、政策文件和抓取原文复制到带时间戳的备份目录。备份操作不能删除或修改当前运行数据。

### 18.5 数据恢复

恢复前必须停止写入操作并校验备份文件完整性。恢复失败时保留现有数据库，不执行半覆盖。

## 19 安全与合规

- 老人身份证号、手机号、服务记录等个人敏感信息不属于本系统首版数据范围。
- 政策资料和测算数据默认保存在本机，不上传第三方在线解析服务。
- 抓取文件保存时校验内容类型、大小和文件名，不允许路径穿越。
- 文件下载通过数据库 ID 定位，不暴露任意文件系统路径。
- 抓取程序阻止访问本机敏感端口、私有网段和非 HTTP 协议。
- Demo 没有登录和权限控制，禁止接入个人敏感数据或直接用于生产环境。
- 日志不得打印完整敏感文件内容、访问令牌或本地绝对路径。
- 删除数据前必须有明确确认；计算快照和审核记录优先归档而不是永久删除。
- 政策原文引用应保留来源，不改变文件内容或发布机关信息。

## 20 非功能需求

### 20.1 性能

- 普通列表和仪表盘 API 在本地典型数据量下应在 2 秒内返回。
- 单城市 U1 测算应在 3 秒内完成。
- 页面首次可操作时间目标为 3 秒以内。
- 单次官网抓取默认 15 秒超时，最大 60 秒。

### 20.2 可靠性

- 数据库写入使用事务。
- 文件写入先写临时文件，再原子替换。
- 抓取失败不影响已有政策记录。
- 单城市计算失败不阻断其他城市的仪表盘。
- 应用重启后数据和状态保持一致。

### 20.3 可维护性

- 前端不复制后端公式。
- 仪表盘聚合由服务端统一完成。
- 参数和公式使用稳定编号。
- 数据库迁移脚本可重复执行。
- API 错误使用稳定错误码。
- 核心业务逻辑必须有自动化测试。

### 20.4 兼容性

- 支持当前主流桌面版 Chrome、Edge 和 Safari。
- 页面最小桌面宽度按 1280 像素设计，并支持更窄屏幕降级。
- 中文文件名、城市名称和政策标题必须正确显示和导出。

### 20.5 可测试性

- U1 参数、阶段、公式和基准结果分别测试。
- SQLite 持久化测试需要覆盖关闭后重新打开数据库。
- 爬虫测试使用本地 HTTP 测试服务，不依赖真实官网。
- 仪表盘测试验证聚合口径和城市范围切换。
- 政策测试验证建议值未采用前不会进入城市实际参数和正式测算。

## 21 异常与边界处理

| 场景 | 系统处理 |
|---|---|
| 没有城市 | 首页显示新增城市引导 |
| 城市没有有效测算 | 城市仍显示，但不计入金额合计 |
| 参数缺失 | 阻断测算并定位具体字段 |
| 参数修改后未重算 | 保留旧快照并显示待重算 |
| 公式除零 | 保留公式错误，不改成零 |
| 数量级异常 | 返回结果并显示待业务确认警告 |
| 政策原文重复抓取 | 提示内容未变化，不生成重复文件实体 |
| 官网地址无效 | 阻止抓取并提示 URL 问题 |
| 官网超时 | 保存失败记录，不删除旧版本 |
| 官网内容未变化 | 记录本次检查并标记无变化 |
| 官网内容变化 | 创建新抓取记录并生成新的建议值 |
| 抓取内容超过上限 | 中止保存并记录大小限制错误 |
| 建议值未采用 | 只显示为灰色提示，不参与计算 |
| 导出部分失败 | 返回明确错误，不生成不完整 ZIP |
| 数据库迁移失败 | 终止启动并保留原数据库 |

## 22 验收标准

### 22.1 总览仪表盘

1. 根路径默认显示全部城市总览。
2. 可以切换全部城市、单城市和多城市对比。
3. 每个城市默认只取最新有效测算快照。
4. 指标卡、趋势图和城市比较使用同一筛选范围。
5. 缺失、待重算和失败状态不会被静默当成有效数据。
6. 风险提醒可以跳转到对应项目或政策资料。

### 22.2 城市测算

1. 可以新增城市和初始场景。
2. 可以按分组修改并保存参数。
3. 必填参数缺失时无法执行正式测算。
4. 成功测算生成 24 个月结果和不可变快照。
5. 修改参数后场景变为待重算。
6. 重算产生新快照，历史快照仍可查看。
7. 新快照自动同步到仪表盘。

### 22.3 政策资料

1. 可以按全部城市或单城市查看政策资料。
2. 可以新增、编辑、启用和停用固定官网来源。
3. 可以从前端触发一次一键抓取。
4. 抓取后保存原文、状态码、时间、内容类型和指纹。
5. 相同内容和变化内容可以区分。
6. 抓取失败不影响上一次成功记录。
7. 可以查看与 Excel 参数编号关联的建议值。
8. 建议值以灰色占位文字显示，点击采用后才写入真实参数。
9. 用户手工填写可以覆盖建议值，并保留建议值来源和历史。
10. 可以导出 CSV、JSON 和原始文件 ZIP。

### 22.4 模型复刻

1. 基准输入可以生成 24 个月结果。
2. 关键结果可以追溯到参数编号、Excel 单元格和公式台账。
3. 已登记公式疑点和公式错误不会被隐藏。
4. 空值、零值、公式错误和待确认状态可区分。
5. 修正公式时创建新模型版本，不改变旧结果。

### 22.5 本地数据

1. 初始化可以创建 SQLite 和数据目录。
2. 项目、测算和政策数据在应用重启后仍然存在。
3. 备份包含数据库、政策文件和抓取原文。
4. 重复初始化不会覆盖已有数据。

## 24 待业务确认事项

### 24.1 站点覆盖失能客户公式

`控制台!E32` 的最后一项使用 `E12 × 0.1`，而 `E12` 当前表示区域人口密度。第一版保留原公式，并标记 `SUSPECTED_CELL_REFERENCE`。

### 24.2 筹备期净利率

筹备期累计收入为 0 时，`阶段汇总表!B12` 会出现 `DIV0`。第一版保留公式错误，不显示为 0 或空值。

### 24.3 累计净利润指标

`核心指标卡!C9` 当前通过 `SUM(B32:Y32)` 再次求和累计序列。第一版继续复刻，同时标记 `CUMULATIVE_SERIES_SUM`。

### 24.4 客户和收入数量级

当前基准输入会产生较大的站点客户数和收入结果。第一版不做限幅、隐藏或隐式单位换算，等待业务确认城市总量、区域总量、覆盖范围和目标市场覆盖率之间的口径。

### 24.5 政策字段标准

服务单价、待遇上限、服务频次、基金支付比例和人员要求在不同城市可能采用不同单位和适用条件。正式跨城市比较前，需要确认统一字段定义和换算规则。

### 24.6 官网抓取范围

首版按单个固定 URL 抓取。是否需要自动识别栏目分页、递归下载附件和按关键词筛选，需根据首批官网样例决定。

### 24.7 Demo 开放操作说明

Demo 阶段不区分结果确认权限，所有访问者都可以运行测算、查看结果和导出数据。该开放模式只适用于演示数据，正式上线前必须增加登录和写入权限控制。
