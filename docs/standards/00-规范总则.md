# UE Agent 开发规范总则

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 规范版本 | v0.2 |
| 生效日期 | 2026-09-08 |
| 适用范围 | UE Agent 全仓库 |
| 当前产品阶段 | U1 单站 UE 测算设计与开发 |
| 规范目标 | 让人工开发和 Vibe Coding 产出保持同一架构、组件、视觉和质量标准 |

本规范是 UE Agent 的工程约束入口。后续开发者或 AI Agent 在修改代码前，必须先阅读本文件和对应目录的规则文件。

## 2. 设计判断

UE Agent 是面向业务人员、城市负责人和管理层的高密度决策后台，不是营销网站。

- 设计变化度：3/10。优先稳定、可预测和易学习。
- 动效强度：2/10。仅保留状态反馈和必要过渡。
- 信息密度：7/10。支持参数表、来源说明、月度投影和审核记录。
- 主题：首版只提供浅色主题。
- 风格：专业、克制、可信、来源可追溯。

## 3. 规范优先级

发生冲突时按以下顺序处理：

1. 已确认的业务口径和计算规则。
2. 模型版本说明、架构决策记录和数据契约。
3. `docs/standards/` 下的本规范。
4. 仓库内已存在并通过验收的实现模式。
5. 第三方示例、AI 建议和个人偏好。

不得以“第三方项目这样写”或“AI 默认生成”为理由覆盖前三级规则。

## 4. 不可协商规则

1. 核心财务结果由确定性计算引擎生成，大模型不得直接给出或修改结果。
2. 参考值、人工确认值、计算值和展示值必须分层保存，不能混成一个字段。
3. 正式计算必须绑定模型版本、输入快照和来源版本。
4. 公开数据不能静默覆盖人工确认值。
5. 缺失、零值、不适用和计算失败必须使用不同状态表达。
6. 前端只能使用一套基础组件系统和一套图标系统。
7. 页面禁止硬编码品牌颜色、圆角、阴影和层级值。
8. 新页面必须覆盖正常、加载、空、错误、无权限和数据过期状态。
9. 新增依赖、设计 token、基础组件或全局样式必须说明复用判断和影响范围。
10. 未通过类型检查、测试、构建和前端验收清单的改动不能进入可发布状态。

## 6. 变更流程

以下变更必须先写架构决策记录，再改代码：

- 更换 Next.js、FastAPI、数据库或任务队列。
- 引入第二套 UI、图表、表格、表单或图标库。
- 修改主色、字体、基础圆角或页面骨架。
- 改变模型公式、参数单位、现金流口径或版本规则。
- 将首版浅色主题扩展为双主题。
- 让爬虫结果自动影响正式测算。

架构决策记录至少说明问题、候选方案、最终选择、影响范围、迁移方案和回退方案。

## 7. 例外处理

遇到规范无法覆盖的场景时，不得静默绕过。开发者必须：

1. 说明现有组件或规则为什么无法满足。
2. 提供最小范围的例外方案。
3. 说明是否产生新 token、依赖或公共 API。
4. 补充测试和验收方式。
5. 经确认后再实施。

一次页面的特殊需求不能自动升级为全局设计规则。

## 8. Vibe Coding 调研依据

本套规范采用当前主流 AI 开发工具的共同做法：

- Cursor 将可复用规则保存在版本化的 `.cursor/rules`，并支持按路径和 glob 自动应用。
- GitHub Copilot 支持仓库级 `.github/copilot-instructions.md`、路径级 instructions 和 `AGENTS.md`。
- v0 建议使用 `globals.css`、Tailwind token 和 shadcn registry 向生成模型传递设计系统上下文。
- shadcn/ui 使用 `components.json` 固定组件风格、CSS Variables、路径 alias 和 registry。
- Tailwind CSS v4 使用 theme variables 把设计 token 映射为稳定 utility API。
- 成熟开源项目通常把共享组件集中到独立 UI 包，而不是在各页面复制组件。
