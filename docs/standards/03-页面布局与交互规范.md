# 页面布局与交互规范

## 1. 应用骨架

桌面端统一使用：左侧导航 + 顶部上下文栏 + 主内容区。

| 区域 | 标准 |
|---|---|
| 左侧导航 | 展开 240px，收起 64px |
| 顶部栏 | 56px |
| 内容最大宽度 | 1440px |
| 内容区 | 12 列网格，24px gutter |
| 页面内边距 | 桌面 24px，平板 20px，手机 16px |

顶部栏固定展示当前项目、城市/区县、模型版本和测算状态。页面不得各自重新实现导航和顶部栏。

## 2. 导航结构

首版导航顺序固定为：

1. 项目管理
2. U1 单站测算
3. 城市资料
4. 政策中心
5. 多城市对比（未开放时明确标注）
6. 后台管理

导航文字使用业务名称，不使用“工作台 2.0”“智慧中心”等空泛名称。

## 3. 标准页面模板

### 3.1 列表页

顺序固定为：

1. PageHeader：标题、简短说明、主操作。
2. FilterBar：搜索、城市、状态、模型版本和时间。
3. 数据完整度或风险摘要（确有必要时）。
4. DataTable。
5. 分页和结果数量。

筛选状态写入 URL。刷新页面和分享链接后，筛选条件必须保持。

### 3.2 U1 参数填写页

使用“三栏分步工作区”：

- 左侧 200px：步骤和完成状态。
- 中间：当前步骤表单，最大宽度 760px。
- 右侧 320px：参考值、来源、更新时间、可信度和口径说明。

小于 1200px 时右侧来源栏改为 Sheet；小于 768px 时步骤栏改为顶部进度和下拉选择。

每个参数至少展示：名称、编号、填写值、单位、说明、来源状态和校验结果。参考值必须通过明确按钮填入，不能自动覆盖。

### 3.3 参数复核页

按业务区块分组展示已填写值、参考值差异、缺失项和异常项。用户运行测算前必须能定位所有阻断项。

只允许一个主按钮“运行测算”。存在阻断错误时按钮禁用，并在页面内列出原因。

### 3.4 结果页

顺序固定为：

1. 测算上下文：项目、场景、城市、模型版本、计算时间。
2. 核心结果：回收期、最大资金缺口、平台期净利润、盈亏平衡客户数。
3. 24 个月收入、成本、净利润和累计现金流趋势。
4. 阶段汇总。
5. 月度明细表。
6. 参数和公式口径说明。
7. 来源与输入快照。

核心指标最多六项。不是所有数字都做成卡片。金额默认使用千分位，负数使用明确负号，不能只靠红色区分。

### 3.5 政策中心

列表页显示政策名称、适用区域、发布机关、文号、生效日期、状态、更新时间和来源。

详情页分为原始文件、结构化摘要、准入要求、申报材料、版本历史和来源记录。AI 提取内容必须标注“待审核”或“已审核”。

### 3.6 后台配置页

配置项采用表格或分组表单，不使用自由画布。涉及模型参数时显示影响范围、当前版本和变更后是否需要发布新版本。

## 4. 交互状态

每个异步模块必须实现：

| 状态 | 展示要求 |
|---|---|
| 初始 | 明确可执行动作 |
| 加载 | 使用与最终内容形状一致的 Skeleton |
| 空 | 说明为什么为空和下一步操作 |
| 成功 | 页面数据更新，必要时使用短 Toast |
| 错误 | 在出错区域展示原因和重试入口 |
| 无权限 | 说明缺少的权限和可联系角色 |
| 数据过期 | 显示更新时间、影响和刷新方式 |

不得使用全屏 Spinner 代替局部加载。Toast 不得承载必须长期可见的错误和业务风险。

## 5. 测算状态

场景至少包含以下状态：

- `draft`：正在填写。
- `ready`：校验通过，可以运行。
- `calculating`：正在计算。
- `calculated`：结果与当前输入一致。
- `stale`：输入已修改，旧结果失效。
- `failed`：计算失败。
- `confirmed`：结果已由有权限角色确认。

修改任何参与计算的参数后，状态立即变为 `stale`。旧结果可以查看，但必须显示明显失效提示，不能冒充当前结果。

## 6. 表单交互

- 自动保存时必须显示“保存中”“已保存”或“保存失败”。
- 离开未保存页面前提醒用户。
- 数字输入允许临时空值，不得在输入过程中强制变成 0。
- 百分比的存储值和展示值必须在字段定义中固定。
- 超出合理范围时提示，不得擅自改回默认值。
- 一键填入参考值属于用户操作，写入后记录来源和时间。
- 覆盖参考值时保留原参考值，不覆盖来源记录。

## 7. 操作反馈

- 保存草稿、复制场景等可恢复操作使用普通确认反馈。
- 删除、作废、发布模型等高影响操作必须二次确认。
- 二次确认文案必须说明对象和影响，禁止仅写“确定吗？”
- 按钮提交后进入 loading，防止重复提交。
- 操作成功后优先更新当前页面数据，不通过刷新整页掩盖状态问题。

## 8. 响应式规则

| 宽度 | 行为 |
|---|---|
| `< 768px` | 单列；侧栏改抽屉；表格保留关键列并支持详情展开 |
| `768-1199px` | 导航可收起；右侧说明改 Sheet |
| `>= 1200px` | 完整三栏测算工作区 |

每个多列页面必须明确移动端降级方式。不得假设 Tailwind 自动堆叠就能形成可用移动页面。

## 9. 文案规范

- 使用业务人员能理解的中文。
- 按钮使用动词加对象，如“保存草稿”“复制场景”“查看来源”。
- 错误说明具体字段和原因，不使用“系统异常，请稍后重试”覆盖全部错误。
- 不使用营销式词语、夸张表达和自创概念。
- 同一对象全站使用同一名称，例如统一使用“场景”，不混用“方案”“版本方案”。

## 10. 禁止事项

- 不在页面内重新创建应用导航。
- 不让同一操作同时出现在多个主按钮位置。
- 不用 Modal 承载长表单；长内容使用独立页面或 Sheet。
- 不把所有异常都做成 Toast。
- 不用颜色代替状态文字、单位或正负号。
- 不为了减少滚动缩小字号或压缩到不可读。
- 不在窄屏隐藏关键风险和来源信息，只能改变呈现方式。
