# U1 已知问题与待业务确认

本页对应 [`u1.issues.json`](../../packages/model-spec/issues/u1.issues.json)。这些问题是当前 Excel 的复刻风险，不代表本系统已经确认其为业务错误。

## `控制台!E32`：末项引用已按业务确认修正（2026-09-10）

- **问题代码**：`SUSPECTED_CELL_REFERENCE`（状态已由 `needs_business_confirmation` 更新为 `resolved_by_business_decision`）
- **原行为**：站点覆盖失能客户上限公式最后一项使用 `E12*0.1`（区域人口密度）。
- **问题**：`E12` 是区域人口密度（人/km²），被当作「失能率」参与三年龄段加权，量纲失配。
- **业务确认**：2026-09-10 确认末项应为 `C8`（80 岁以上失能率），已修正 `formulas.py::station_coverage_disabled_limit`。
- **数值对比（基准输入：`S1=3`、`C9=20000`、`C4=0.2`、`C6=0.002`、`C7=0.008`、`C8=0.025`）**：

| | 修正前（末项 C9） | 修正后（末项 C8） |
|---|---|---|
| S5 站点覆盖上限 | 226,195,078（2.26 亿人） | 689.89 |
| 站点覆盖客户（×S8=0.5） | 113,097,539 人 | 344.95 人 |
| 平台期月均收入 | 2205.4 亿元 | 67.3 万元 |
| 平台期月均净利润 | 2201.4 亿元 | 51.6 万元 |
| 平台期净利率 | 99.8% | 76.8% |

修正后量级回到现实区间，月度客户爬坡（57.5 → 115 → 172.5 → … → 344.95）与逐月损益也恢复常态。

- **连带变更**：最大现金缺口由 -501,000 变为 **-556,639.61**（收入回归真实后，第 2 个月转为净亏，现金流继续下探）；24 个月累计净利润由 4.8E+13 变为 **1.03E+08**。fixture `u1-baseline.json` 缓存已同步重算。

### 遗留疑点：S3 与 S5 是否应共用同一算式

- **问题代码**：`SHARED_FORMULA_STRUCTURE`
- **现象**：末项统一为 `C8` 后，S3（护理员日工作时段，单位 **小时**）与 S5（站点覆盖失能客户上限，单位 **人**）的公式结构完全相同，基准输入下同为 `689.89`，但单位语义不同。
- **判断**：不同量纲的字段得出同一个数，逻辑上仍不自洽。本次修正解决了数量级错误，但两字段是否确应采用同一算式**仍需业务方复核**。
- **备选理解**：S5 可能应为「面积 × 人口密度 × 失能率」类的人口上限公式，而非复用 S3 的年龄段加权结构。若业务方给出准确定义需新增模型版本。

## 公式字段的显示前提（前端行为说明）

- **不是缺陷**：`公式自动` 字段（`C9/P3/S3/S5/B16`）的值来自测算结果 `result.parameters[fieldId]`，因此**只有执行过测算（`status=calculated`）后才会显示数值**；场景处于 `draft` 且 `result` 为 `null` 时显示为空且只读，属预期行为。
- **可选改进（待评审）**：草稿态下可对公式字段显示「待测算」占位文案，避免被误判为功能异常。

## `阶段汇总表!B12`：筹备期净利率 `DIV0`

- **问题代码**：`DIV0_IN_SUMMARY`
- **当前行为**：筹备期累计收入为 0，`B8/B5` 返回 `#DIV/0!`。
- **本版本处理**：使用 `FormulaValue(status="formula_error", error_code="DIV0")` 表达，不改成 0、不改成空值。

## `核心指标卡!C9` / `AB32`：累计序列求和

- **问题代码**：`CUMULATIVE_SERIES_SUM`
- **当前行为**：`AB32 = SUM(B32:Y32)`，把每个月的累计净利润再次求和。
- **疑点**：如果业务要的是第 24 个月累计净利润，通常应直接取 `Y32`；但当前版本不替换 Excel 逻辑。
- **本版本处理**：headline 指标继续复刻 `SUM(B32:Y32)`，同时在问题列表中标记待业务确认。

## 核心指标卡口径（2026-09-10 对齐）

Excel「核心指标卡」共 10 项，后端 `headline_metrics` 实现如下（数值以基准输入复核）：

| Excel 指标 | 单位 | headline_metrics key | 口径 |
|---|---|---|---|
| 投资回收期 | 月 | `payback_month` | 累计现金流首次回正的月份 |
| 启动期累计最大亏损 | 元 | `startup_max_cash_deficit` | 筹备期 + 启动期累计现金流最低点 |
| 平台期月均净利润 | 元/月 | `platform_monthly_net_profit` | 平台期净利润均值 |
| 平台期月均净利率 | % | `platform_net_margin` | 平台期总净利 / 总收入 |
| 24个月累计净利润 | 元 | `twenty_four_month_cumulative_net_profit` | `SUM(累计净利润)`，复刻 `SUM(B32:Y32)` |
| 盈亏平衡月份 | 月 | `net_break_even_month` | 累计净利润首次为正的月份 |
| 平台期盈亏平衡客户数 | 人 | `break_even_customers` | 平台期固定成本 / 单客户贡献 |
| 筹备期总投入 | 元 | `initial_investment` | 控制台 B16 |
| 启动期总亏损 | 元 | `startup_total_loss` | 启动期净利润累计值 |
| 平台期月均收入 | 元/月 | `platform_monthly_revenue` | 平台期总收入均值 |

说明：

- `startup_max_cash_deficit` 与 `max_cash_deficit` 在基准输入下同为 `-501000`（第 1 个月筹备期的现金流最低点），符合 Excel 指标卡两处显示相同数值的现象。
- `net_break_even_month`（净利润口径）与 `payback_month`（现金流口径）语义不同，Excel 说明分别为「累计净利润首次为正」与「累计现金流回正」，不可混用。
- `startup_total_loss` 在 S5 公式疑点未修正前会呈现为大额正数（虚假盈利），与 Excel 中该格标红表达亏损意图不符，根因是 `控制台!E32` 的量纲问题，见上节。

## 数量级异常

基准输入会产生非常大的站点客户数和收入结果。这一版本不通过四舍五入、限幅、`IFERROR` 或隐式单位换算改变结果；后续业务评审需确认城市总量、区域总量、站点覆盖范围和目标市场覆盖率的边界关系。
